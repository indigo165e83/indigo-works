個人開発しているフリー素材サイト「[Free Images](https://free-images.indigo165e83.com/)」に、サーバー代の足しにするための投げ銭機能を導入しようとしました。

決済といえば **Stripe**。APIも使いやすく、エンジニアならこれ一択だろうと意気揚々と実装を始めたのですが、結果として**審査に通過できず、アカウント閉鎖（BAN）**という悲しい結末を迎えました。

そこから **GitHub Sponsors** に移行するまでの、「決済審査の厳しさ」と「個人開発者にとっての最適解」についての記録を残しておきます。

{/* excerpt */}

## Stripe導入のきっかけ

Stripeには **Payment Links** というノーコードで決済リンクを発行できる機能があり、これをサイトのフッターに貼るだけで実装は完了しました。

技術的には非常に簡単だったのですが、問題は**「運用と規約」**の壁でした。

## 第1の壁：「寄付 (Donation)」という言葉の重み

アカウントを作成し、商品を「寄付」という名前で登録して公開したところ、すぐにStripeから警告メールが届きました。

> **Stripeからの連絡 (要約)**
>
> 1. あなたのサイトにはコンテンツがありません（※AI画像サイトなので誤検知）。
> 2. コンテンツに対する報酬に **「寄付 (Donation)」** という表現が使われています。Stripeでは「寄付」を処理できるのは**登録された慈善団体や非営利団体に限られています**。
> 3. 個人クリエイターの場合は **「チップ (Tip)」** という表現を使用してください。

なるほど、言われてみればその通りです。「寄付」という言葉は法的にデリケートです。
私はすぐにサイト内の文言を `Donate` から `Support / Tip` に書き換え、Stripeの商品名も「Free Imagesへのチップ」に変更して、再審査を依頼しました。

「これで文言の問題はクリアしたし、コンテンツもちゃんとあるサイトだと伝えれば大丈夫だろう」と高を括っていました。

## 第2の壁：ビジネスモデルの非承認

修正報告をしてから数時間後、Stripeから無慈悲なメールが届きました。

> **Stripeからの連絡**
>
> 残念ながら、現時点では、Stripe は貴社のビジネスをサポートできません。弊社には、サポートできる業種に関する厳格な制限事項があり、貴社のビジネスモデルは制限対象に該当すると見受けられます。

**一発アウトです。**

「寄付」を「チップ」に変えただけではダメだったのか、あるいは「AI生成画像の提供」というビジネスモデルがハイリスクと判断されたのか、詳細な理由は明かされません（セキュリティ上の理由で教えてもらえないことがほとんどです）。

個人開発者が「運営支援」を募るというシンプルな用途でも、決済代行会社（特にグローバルなプラットフォーム）のコンプライアンス基準をクリアするのは、想像以上にハードルが高いことを痛感しました。

これ以上粘ってブラックリスト入りするのも怖いため、Stripeでの実装はここで断念しました。

## 救世主：GitHub Sponsors

Stripeのアカウントが閉鎖され、途方に暮れていた時に思い出したのが **GitHub Sponsors** です。

灯台下暗し。エンジニアである私たちが普段使っているGitHubにこそ、最適な機能がありました。

### GitHub Sponsorsを選んだ理由

1.  **開発者への支援に特化している**
    「コードを書いている人」「OSS活動をしている人」への支援という文脈が確立されているため、Stripeのような「ビジネスモデルの審査」で弾かれるリスクが低いです。
2.  **手数料が安い（または無料）**
    GitHub Sponsorsは、個人の場合、決済手数料をGitHub側が負担してくれるケースが多く（※時期やプランによります）、受け取り手にとって非常に有利です。
3.  **実装が不要**
    プロフィールページに「Sponsor」ボタンが出るだけでなく、リポジトリに `.github/FUNDING.yml` を置くだけで、各リポジトリにスポンサーボタンを表示できます。

### 導入手順

導入は拍子抜けするほど簡単でした。

1.  GitHubの設定から `Sponsors` を有効化し、プロフィールなどを入力して申請。
2.  リポジトリに `.github/FUNDING.yml` を作成。

```yaml
FUNDING.yml
github: [your-username]
```
これだけで、リポジトリのサイドバーに「Sponsor」ボタンが表示されるようになります。
StripeのAPIキー管理やWebhookの実装、規約の文言修正に費やした時間は何だったのでしょうか。

## 教訓
「個人開発の投げ銭は、餅は餅屋（GitHub Sponsors）に任せろ」

もちろん、本格的なSaaSを作ってサブスクリプションで収益化するならStripeが最強のツールであることは間違いありません。
しかし、今回のような「フリー素材サイトへの少額の支援」や「開発者へのチップ」という用途であれば、GitHub Sponsors や Buy Me a Coffee のような、クリエイター支援に特化したプラットフォームを使うのが正解でした。

もし同じようにStripeの審査で消耗している個人開発者の方がいたら、早めにGitHub Sponsorsへの切り替えを検討することをお勧めします。
